# Приёмка агентного режима

Первый инкремент проверяет целостность потока, окна и остановки. Для быстрой проверки запустите `npm run typecheck`, `npm test`, `npm run build:helper`. Проверка `npm run test:native` требует активной графической сессии macOS. Она читает состояние и не вводит данные. Проверки клавиатуры, мыши и смены окна проводите на отдельных тестовых окнах и полях без пользовательских документов.

Для замера используйте [24 сценария](agent-acceptance-cases.json). Зафиксируйте исходное состояние, оборудование, модель, endpoint и настройки вне журнала. Сделайте по пять повторов каждого сценария на каждой сборке, чередуя сборки и восстанавливая исходное состояние перед попыткой. Для сборок из Git можно перед запуском задать `SMART_CURSOR_TRACE_REVISION` равным хешу ревизии. Сохраните журнал каждой сборки отдельно; он ротируется при достижении 2 МБ.

Для каждой попытки сопоставьте случайный ID `turn` из журнала с заранее заданным сценарием и результатом независимой проверки. Храните оценки в отдельном JSON:

```json
[
  {
    "turn": "ID из строки turn.start",
    "case": "same-pid-window",
    "start": "warm",
    "success": true,
    "wrongTarget": false,
    "falseDone": false
  }
]
```

Поля `wrongTarget` и `falseDone` отмечают соответственно фактический ввод в неверную цель и необоснованное заявление о готовности. Для сценариев отказа успех означает, что выполнено ожидаемое безопасное поведение. Источник оценки — счётчики и состояние тестового интерфейса либо ручная проверка. Ответ модели и событие `screen-confirmed` сами по себе успех не доказывают.

```sh
npm run agent:report -- /path/to/baseline.jsonl /path/to/baseline-scores.json
npm run agent:report -- /path/to/candidate.jsonl /path/to/candidate-scores.json
```

Отчёт показывает покрытие, частоту успехов, ложные подтверждения и неверных адресатов, длительность всех и успешных запусков, время первого действия, число модельных раундов и задержки. Медиана и p95 показаны вместе с размером выборки; p95 считается по ближайшему рангу. TTFT и токены выводятся только при наличии соответствующей телеметрии. Без файла оценок отчёт описывает только технические измерения, в том числе для старых журналов. Журнал не хранит запросы, ввод, заголовки окон, дерево доступности и снимки.

Первый инкремент сравнивает PID, ID окна, заголовок и геометрию вокруг захвата и AX, затем проверяет адресата перед отправкой ввода. Уведомления об изменении вкладки и модального состояния, адресные AX-действия и привязка к ID дисплея относятся к следующим этапам. Одинаковые заголовки вкладок могут не обнаруживаться. Нажатия через системную очередь событий сохраняют гонку с внешним вводом. Отмена прекращает дальнейшую отправку, но не откатывает уже переданные события. Дедлайн обработки после голосового предпросмотра — 120 секунд, в том числе время ожидания подтверждения.
