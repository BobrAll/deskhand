# Проверка ожидания

Ветка: `codex/friendly-waiting`.

## Запуск

Закройте уже запущенный Smart Cursor через меню в трее, чтобы не мешал второй экземпляр.
Из корня проекта выполните `npm run dev`.

1. Откройте карточку привычной горячей клавишей и задайте текстовый вопрос.
   Если ответ ещё не появился, через 1,5 секунды появится «Готовлю ответ…».
   Через 8 секунд появится одна локальная подсказка. Через 25 секунд — сообщение
   о долгом ожидании. Быстрый ответ не должен показывать подсказки.
2. В настройках → «Голос» проверьте «Короткие реплики агента» (включены по умолчанию).
   Введите или произнесите «Открой новую вкладку» в Chrome. Подсветка курсора должна
   появиться до готового плана; Cmd+T не должен вызывать диалог разрешения.
   Для обычных голосовых вопросов выберите «Голосом ответа» → «Системный» или
   «Нейроголос»: по умолчанию ответ читается на карточке, а не вслух. Голос,
   адрес сервиса, модель, стиль и ключ задаются в группе «Синтез речи».
   Если готовой фразы ответа нет 1,5 секунды, прозвучит короткая заготовка голосом
   ассистента. Настоящий ответ прерывает её, а не встаёт за ней в очередь.
   Для следующей заготовки подождите 45 секунд: действует ограничение частоты.
3. Во время ожидания нажмите Esc, кнопку остановки или начните новую запись.
   От старого запроса не должны позднее звучать реплики.
4. Дайте агенту обычную безопасную задачу в тестовом приложении. Его реальные
   шаги должны оставаться видимыми; при долгой работе под ними появляется подсказка.
5. Выключите «Короткие реплики агента»: подтверждения ожидания команд пропадут.
   «Голосовой диалог» отдельно управляет чтением ответов на голосовые вопросы.
   Обычные текстовые вопросы не сопровождаются заготовками.

Голосовая карточка по-прежнему может скрываться во время запроса: в этом случае
обратная связь — звуковая. Подсказки показываются только в видимой карточке.
Короткие фразы записаны заранее и звучат сразу, без ключа и сети. Ответ по
умолчанию не читается; если включить чтение, голос выбирается в той же вкладке —
системный или нейроголос с собственным endpoint, моделью и ключом.

## Проверка без ожидания медленной модели

`npx vitest run src/renderer/overlay/useWaiting.test.ts src/renderer/overlay/useSpeech.test.ts src/renderer/overlay/speechAudio.test.ts`

Тесты используют виртуальное время: проверяют пороги 1,5 / 8 / 25 секунд, очистку
таймеров, быстрый ответ, приоритет ответа над заготовкой, выключенный диалог,
отмену во время загрузки настроек и ограничение частоты реплик. Сеть не нужна.

Для ручной проверки всех визуальных порогов можно временно увеличить
`WAIT_STATUS_MS`, `WAIT_TIP_MS`, `WAIT_LONG_MS` в `src/renderer/overlay/waiting.ts`
до подходящих для вашей модели значений (или уменьшить, если модель отвечает быстро),
затем вернуть исходные значения. Проверка голосов требует реального запуска на macOS.
