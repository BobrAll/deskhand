# Выпуск релиза

## 1. Подготовка

- Номер версии меняется в `package.json` и `package-lock.json` в отдельной ветке от `dev`, изменение фиксируется коммитом.
- Запускаются проверки: `npm run check` (типы, линтер, форматтер, тесты).
- Ветка сливается в `dev` после подтверждения.

## 2. Сборка

- `npm run build:native` собирает четыре нативные программы: `deskhand-helper`, `whisper-cli`, `transcribe-cli`, `deskhand-agent`. Нужны Xcode Command Line Tools, CMake и сеть: скрипты клонируют whisper.cpp и transcribe.cpp. Сборка занимает несколько минут и всегда делает universal-бинарники.
- `npm run dist` собирает только приложение и не собирает нативы. Пропущенный бинарник всплывёт лишь на шаге `prepare-release.mjs`, после прогона electron-builder.
- Результат в `release/`: `.zip`, `.dmg`, их `.sha256` и `install.sh`.
- Скрипт `prepare-release.mjs` проверяет подпись, наличие всех бинарников, их universal-архитектуры, модели и лицензий движков.

## 3. Слияние и тег

- `dev` сливается в `main` после подтверждения.
- На коммит в `main` ставится тег `v1.0.0`. Он фиксирует, из какого кода собран релиз.

## 4. Черновик и проверка

- На GitHub создаётся черновик релиза с файлами из `release/`. Черновик виден только участникам репозитория.
- Установка через `install.sh` проверяется на чистом Mac: приложение запускается, разрешения выдаются и работают.

## 5. Публикация

- После успешной проверки и подтверждения черновик публикуется.
- С этого момента файлы доступны всем, а ссылка `/releases/latest/download/…` указывает на новую версию.
- Уже установленные копии не обновляются: для обновления заново запускается `install.sh`.

> Слияния, создание тега и публикация выполняются только с явного подтверждения. Публикацию нельзя отменить, поэтому проверка черновика обязательна.
