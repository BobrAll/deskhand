# Озвучка и синтез речи

Тексты реплик и правила их использования описаны в [голосовых заготовках](voice-phrases.md).

## Как это устроено в коде

Голос — это два независимых слоя, и путать их нельзя.

**Слой 1. Записанные фразы.** 85 реплик состояния из `src/shared/speechBank.ts`
лежат готовыми файлами в `src/renderer/overlay/speech/`. Они звучат всегда:
без ключа, без сети, без настроек, мгновенно. Это и есть «голос ассистента» по
умолчанию. Рядом `manifest.json` — точный текст, из которого записан каждый
файл; если фразу переписали, файл перестаёт совпадать и просто не играет,
вместо того чтобы сказать одно, а показать другое.

**Слой 2. Живой синтез.** Необязательный. Настраивается целиком в
«Настройки → Голос → Синтез речи», и у него два движка:

- **Silero · V5.6 RU** — локальная русская модель, скачивается по кнопке:
  Python-рантайм `silero-onnx-tts` в `userData/silero/venv` и ~300 МБ ONNX-весов
  из закреплённого релиза. Нужны Python 3.12+ и сеть только на время загрузки;
  дальше синтез идёт офлайн. Единственное исключение — необязательное уточнение
  произношения у текстовой модели, его можно выключить. Это экспериментальный
  движок: он не входит в бандл, а лицензия весов — CC BY-NC-SA 4.0, только для
  некоммерческого использования.
  Латиницы в словаре Silero нет, поэтому английские слова пишутся русскими
  буквами («README» → «р+идми»). Словарь терминов — затравка: он покрывает
  частые слова и несёт ударение. Незнакомое слово один раз уточняется у
  настроенной текстовой модели (`src/main/tts/pronounce.ts`), ответ кэшируется
  в `userData/tts-pronunciation.json`, а при недоступности модели или при
  выключенном тумблере «Уточнять произношение» работает стресс-модель Silero.
  Карточка и настройки показывают исходный текст: транслитерация и
  `+`-ударения живут только в строке для синтеза.
- **Сервис по API** — адрес, модель, голос, стиль подачи и ключ. Ключ лежит в
  `deskhand-secrets.json` с доступом только для твоего пользователя и никогда не
  попадает ни в настройки, ни в renderer, ни в `settings.json`.

Что именно выбрано, решает `tts.engine`; поля одного движка не влияют на другой.

| Источник              | Что звучит                                                                 | Задержка                                                       | Стоимость                                          |
| --------------------- | -------------------------------------------------------------------------- | -------------------------------------------------------------- | -------------------------------------------------- |
| Записанный банк       | Реплики состояния                                                          | 0                                                              | 0 ₽, 0 запросов                                    |
| Кэш на диске          | Любая фраза, которую уже произносили                                       | 0                                                              | 0 ₽, 0 запросов                                    |
| Silero · локально     | Реплики и ответы, если он выбран и скачан                                  | ~3 с на новую фразу; первое незнакомое слово — ещё один запрос | 0 ₽ за синтез; запрос к текстовой модели по тарифу |
| Сервис по API         | Ответы по кнопке «Прослушать» и в режиме «Нейроголос», если синтез включён | один запрос на фрагмент                                        | по тарифу сервиса                                  |
| Системный голос macOS | Режим «Системный» и резерв при недоступном синтезе                         | мгновенно                                                      | 0                                                  |

Почему это не стоит времени:

1. **Записанные фразы не синтезируются в рантайме.** «Сейчас посмотрю.»,
   «Готово.», «Остановил.» — файлы в бандле. Исключение одно: выбранный
   локальный движок Silero читает и эти строки, потому что синтез бесплатный и
   офлайн (кроме необязательного уточнения произношения) — иначе ответы звучали
   бы одним голосом, а служебные реплики — прежним. Запись остаётся запасным вариантом, если движок не
   ответил. У сервиса по API такого исключения нет: там каждая строка — деньги.
2. **Кэш по всей конфигурации.** Ключ кэша — конфигурация движка и текст:
   «адрес + модель + голос + стиль» для API, версия весов, голос и подсказки
   произношения для Silero.
   Поэтому смена голоса не проигрывает старый файл, а одинаковый текст не
   оплачивается дважды. Параллельные запросы одной фразы склеиваются.
3. **Синтез параллелен проигрыванию.** Клип готовится в момент появления
   фразы, очередь ждёт только конца предыдущего звука.
4. **Отказ не блокирует карточку.** Нет ключа, нет сети, 500 — звучит системный
   голос, а панель настроек объясняет, что именно не так.

## Что звучит по умолчанию

Ответ **не читается** — `voice.answerVoice = 'off'`. Причины:

- карточка уже показывает ответ, и озвучка дублирует то, на что человек смотрит;
- длинный ответ системным голосом — самая медленная часть хода;
- живой синтез — это деньги за каждый ответ, а решение о тратах не должно
  приниматься за пользователя.

Опции в настройках: «Не читать» (по умолчанию), «Системный» (бесплатно,
офлайн, без ключа) и «Нейроголос» (только если синтез настроен; иначе тихо
откатывается на системный). Старый `dialogue: true` читается как «Системный»,
чтобы существующие установки ничего не потеряли.

Короткие реплики агента (`agentFeedback`) от этого не зависят: это обратная
связь о работе с машиной, а не повтор текста на экране.

## Как перезаписать банк

Текст живёт только в `src/shared/speechBank.ts`. Файлы и `manifest.json` — его
отпечаток. Порядок при правке фраз:

1. Поменять текст (или добавить строку) в `speechBank.ts`.
2. Перегенерировать `src/renderer/overlay/speech/*.mp3` и `manifest.json`.
   Голос, модель и стиль — те же, что в запросе ниже: это описание того, чем
   записан банк, а не настройка.
3. Запустить `npx vitest run src/renderer/overlay/speechAudio.test.ts`. Тест
   назовёт `id`, для которых нет файла или текст не совпадает с записанным.

Запрос, которым записан банк (ключ подставляется из окружения и в репозиторий
не попадает):

```sh
curl -sS -X POST "$BASE_URL/audio/speech" \
  -H "Authorization: Bearer $KEY" \
  -H 'Content-Type: application/json' \
  -d '{"model":"gemini-3.8-flash-tts:flow","input":"Сейчас посмотрю.","voice":"Kore","instructions":"дружный","response_format":"mp3"}' \
  -o src/renderer/overlay/speech/ack-1.mp3
```

Ответы, которых нет в банке, синтезируются в рантайме и кэшируются в
`userData/tts-cache`; их перезаписывать не нужно.

## Куда это ложится в код

Все состояния проходят через один вход: `speech.say(cue)` в
`src/renderer/overlay/useSpeech.ts`. Что можно произнести, решает
`speaksCue` из `src/renderer/overlay/speechCues.ts`, а какую именно запись из
группы — `speechLine`, тоже там. Поэтому «добавить озвучку состояния» — это один
вызов `say` в точке перехода, а не новая ветка проигрывания.

| Момент     | Точка вставки                                              | Кто решает, что звучит                                               |
| ---------- | ---------------------------------------------------------- | -------------------------------------------------------------------- |
| A1         | `useSpeech.begin` → `acknowledge`                          | Кулдаун 45 с, `agentFeedback` для команды, `answerVoice` для вопроса |
| A2         | `App.tsx`, эффект на `waitStage === 'long'`                | Только голосовой ход                                                 |
| A3         | `App.tsx`, `agent.onEvent`, таймер 45 с на `acting`        | `agentFeedback`                                                      |
| B1         | `App.tsx`, `phase === 'asking'`, один раз на `approval.id` | `agentFeedback`                                                      |
| B2–B4      | `answerAgent` после ответа                                 | `agentFeedback`                                                      |
| C1, C4, C6 | `App.tsx`, конец агентского хода без текста                | `agentFeedback` для команды                                          |
| C2, C3     | `useSpeech.finish`                                         | `answerVoice`; C3 — когда ответ намеренно не читается                |
| C5, C7     | `App.tsx`, ошибка запроса; `timeout` приходит с кодом      | `answerVoice` для письменного хода                                   |
| D1–D5      | `App.tsx`, эффект на `voice.code`                          | Всегда: микрофон уже закрыт                                          |
| E1         | `agent.onEvent` с `code: 'blocked'`                        | `agentFeedback`                                                      |
| E2         | `agent.onEvent` с `code: 'secret'`                         | `agentFeedback`                                                      |

Почему состояние приходит кодом, а не текстом: `VoiceEvent.code`,
`AgentEvent.code` и `StreamEvent.code` — короткие значения, по которым нельзя
промахнуться при правке формулировки. Сопоставление по русской строке ломалось
бы при первом же изменении текста.

## Что звучит в каком режиме

Два тумблера делят состояния между собой, и третьего не нужно:

- `agentFeedback` («Короткие реплики агента») — всё про машину: старт команды,
  долгая работа, вопрос о разрешении, решение, конец агентского хода, отказ
  политики. Это обратная связь о том, что происходит на экране, а не повтор
  ответа.
- `answerVoice` («Голосом ответа») — всё про текст: чтение ответа, его финал и
  ошибка запроса. При «Не читать» карточка и есть канал, поэтому письменный ход
  молчит.
- Микрофонные реплики не зависят ни от чего: нажатие уже закончилось, человек
  ждёт, что услышали, а в диктовке карточки может не быть вовсе.

Одно следствие стоит помнить: при «Не читать» и включённых «Коротких репликах»
агентская команда звучит, а обычный вопрос — нет. Это не рассогласование, а
разные каналы.

## Настройки синтеза

| Поле                      | Где                 | Смысл                                                                                      |
| ------------------------- | ------------------- | ------------------------------------------------------------------------------------------ |
| `tts.enabled`             | `AppSettings.tts`   | Включает живой синтез. Выключен — звучит только банк.                                      |
| `tts.engine`              | там же              | `silero` (локально, на скачиваемых весах) или `remote` (сервис по API).                    |
| `tts.baseUrl`             | там же              | Корень API. Нормализуется как адрес провайдера, `/audio/speech` отрезается.                |
| `tts.model`               | там же              | ID модели синтеза.                                                                         |
| `tts.voice`               | там же              | Имя голоса у сервиса. Отдельно от Silero.                                                  |
| `tts.sileroVoice`         | там же              | Голос Silero; не перезаписывает `tts.voice` из вкладки API.                                |
| `tts.pronunciationLookup` | там же              | Разрешает один запрос к текстовой модели за незнакомое английское слово; ответ кэшируется. |
| `tts.style`               | там же              | Инструкция подачи, уходит как `instructions`.                                              |
| ключ                      | `secrets['tts']`    | Лежит в файле с доступом `0600`, не читается ни одним каналом IPC.                         |
| `voice.answerVoice`       | `AppSettings.voice` | `off` / `system` / `neural` — чем читать ответ.                                            |

Инварианты, которые держат тесты:

- ключ не появляется ни в `settings.json`, ни в объекте настроек
  (`defaults.test.ts`, «never carries a key»);
- смена голоса — новая запись кэша, а не старый файл: у сервиса ключ кэша
  включает адрес, модель, голос и стиль; у Silero — версию весов, голос,
  версию транслитерации и подсказки произношения
  (`src/main/tts/index.test.ts`);
- без ключа, без движка или при отказе сервиса запрос не делается и карточка не
  ломается (там же);
- для Silero нужны venv, веса, английская транслитерация и ударение в словаре
  (`src/main/tts/transliterate.test.ts`); незнакомое слово уточняется у модели,
  невалидный или недоступный ответ откатывается на правила
  (`src/main/tts/pronounce.test.ts`).
