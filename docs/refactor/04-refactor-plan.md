Снимок дерева: `b915162`, 2026-11-04. Основание — `03-audit.md` (A1.5 п.1–11, A3.11, A4.8),

## 0. Что план решает — и что нет

Три проблемы, у которых есть измеренная цена:

1. **`main/overlay.ts` — 1 578 строк, 29 функций, 0 % тестов.** Это 16 % всего `main` и весь смысл
   продукта. Внутри уже прочерчены границы автора (`// ---- agent rounds ----` `:1038`,
   `// ---- verification ----` `:1219`), но они не выражены кодом.
2. **Чистые решения заперты в Electron-модулях.** Геометрия пузыря (`windows.ts:204-357`, 154 строки),
   сборка запроса (`overlay.ts:825-1036`, 212 строк), политика клавиш (`overlay/App.tsx:857-930`),
   маршрутизация чанков (`:377-407`) — всё это определяет поведение и не проверяется ничем. Прецедент
   есть: `pointer.ts` (245 строк, импортирует `electron`) покрыт на 96.6 % фейком окна на 40 строк.
3. **Дубли, которые уже разошлись.** `setWindowOpenHandler` — 4 копии, флаг `/i` есть только у
   `agent/cursor.ts:139`; граница `64…8192` записана трижды (`settings/App.tsx:69,295,559-560`);
   ширины `360/112/80` живут в двух процессах (`windows.ts:22,23,47` и `overlay/App.tsx:50,58,60`);
   `loadPage` — 3 копии; разбор data URL — 3 копии; `bounds → area` — 2 копии в одном файле.

Плюс мелочь, которая чинится в один заход: **7 дефектов гигиены** из A4.8 (#2–#7 механические,
#3 — типовой разрыв контракта `hotkeyError`).

**Чего план не делает:** не чинит R5–R7 (ждут отдельного «ок»), не объединяет `MODIFIER_FLAGS`
(сделает `super+s` валидным хоткеем), не сливает `clamp01`/`cleanLabel`/system-префикс (A3.8:
проблемы нет), не трогает `helper.m`, `index.html` ×5 и токены CSS, не вводит классов вместо `let`
(A4.2: вердикт «не чинить»), не добавляет jsdom без «ок».

Появляется **14 файлов в `src/`** (16, если считать два новых `index.ts` после разноса `windows.ts`),
из них 10 — перенос существующего кода (не новая логика), 2 — данные, которые сейчас продублированы

вырост»: у каждого есть либо два потребителя, либо он вынесен ради теста. Обратная сторона — уходит
один файл (`main/overlay.ts` переезжает в папку) и худеют четыре (`overlay.ts`, `windows.ts`, оба
`App.tsx`).

### 1.2 Правила зависимостей (проверяемые)

1. `shared/*` не импортирует `electron`, `main/*`, `renderer/*`. Сейчас так — держим (проверка:
   `grep -rn "from 'electron'" src/shared` → 0).
2. Новый модуль `main/*` без `electron` обязан иметь тест в `env: node`. Модуль с `electron`
   тестируется фейком окна по образцу `pointer.test.ts:23` (18 тестов), а не моком всего модуля.
3. `renderer/*` импортирует только `@shared/*` и свои локальные модули. `renderer/overlay` не
   импортирует `renderer/settings`; исключение — `onboarding/App.tsx` → `settings/HotkeyField`
   (существует, оставляем).
4. `main/overlay/*` не импортирует `main/windows.ts`. Единственная связь — интерфейс `OverlayHost`
   (`host.ts`), он же остаётся единственным контрактом между контроллером и окном.
5. Числа и таблицы, которые обязаны совпадать в двух процессах (ширины пузыря, коды клавиш), живут
   только в `shared/`. Литерал в двух местах = дефект, а не «стиль».
6. Файл > 500 строк — повод для задачи из этого плана, а не для слоя «на вырост». После плана
   единственный файл > 500 строк — `renderer/settings/App.tsx` (если R16–R17 не влезут) и
   `renderer/overlay/App.tsx` (~950: JSX на 301 строку остаётся на месте).

### Волна 2 — дедупликация данных и окон (R06–R09)

- **Файлы.** новый `shared/keycodes.ts`; `agent/keys.ts:15-104`; `voice/listen.ts:26-113`.
- **Страхующие тесты.** `keys.test.ts` (20) и `voice/listen.test.ts` (59) — оба обязаны остаться
