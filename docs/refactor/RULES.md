# Правила (читать в начале каждой сессии)

## Протокол сессии
1. Прочитай PROGRESS.md, затем RULES.md, затем ТОЛЬКО свою задачу в TASKS.md (первая незакрытая `[ ]`).
   CONTEXT.md читай только нужные разделы (grep по заголовку), не целиком.
2. Делай только эту задачу. Не берись за следующую, даже если контекста много.
3. Проверки: во время работы — только точечные (`vitest run <path>`, `tsc` по необходимости).
   Полный набор `typecheck` + `test` + `build` — ОДИН раз перед коммитом.
4. Коммит (Conventional Commits, англ.), затем обнови PROGRESS.md и поставь `[x]` в TASKS.md.
5. Закончи отчётом ≤8 строк по-русски: что сделано, коммит, что найдено, вопросы, что дальше. СТОП.

## Экономия и анти-зацикливание (жёстко)
- Не читай файлы целиком, если нужен кусок: `grep -n`, `sed -n 'a,bp'`. Большой вывод режь `| head -50` / `| tail -40`.
- Читай только файлы из задачи и их прямые импорты. Всё, что нужно знать об остальном, — в CONTEXT.md.
- Не перечитывай файл, который уже читал в этой сессии. Не запускай команды «для проверки того, что и так знаешь».
- Пиши файлы целиком одним вызовом, а не десятком мелких правок. Несколько тестовых файлов — в одном вызове.
- Не создавай документов, отчётов и скриптов, которых нет в задаче.
- Не гонись за покрытием: задача выполнена, когда покрыты ПЕРЕЧИСЛЕННЫЕ в ней ветки поведения. Остальное — не нужно.
- Лимит попыток: тест/шаг красный → максимум 3 попытки исправить. Не вышло → откати незакоммиченное
  (`git checkout -- . && git clean -fd` только для файлов задачи), запиши в PROGRESS.md раздел Blocked
  (что пробовал, где застрял) и остановись с вопросом ко мне.
- Задача разрослась (>~25 вызовов инструментов или явно не влезает) → закоммить зелёное, запиши остаток
  новыми подзадачами в TASKS.md сразу после текущей, остановись.
- Нашёл постороннее (баг, мусор, идея) → одна строка в BUGS.md или в PROGRESS.md «Заметки», и иди дальше. Не отвлекайся.
- Контекст тяжелеет → закончи на зелёном коммите, обнови PROGRESS.md, остановись. Никогда не оставляй красное/незакоммиченное.

## Жёсткие правила проекта
1. Поведение неприкосновенно: тексты промптов и формат запросов к LLM; синтаксис `@`-разметки и правила
   парсинга (включая молчаливое проглатывание и лимиты); имена IPC-каналов и payload; схема/ключи/дефолты
   electron-store; горячие клавиши; строки UI; протокол helper'а (argv, JSON, имена команд/событий/ошибок);
   пути ресурсов; результат electron-builder.
2. Баги не чинить: запись в BUGS.md (где, как воспроизвести, ожидание) + тест с `// KNOWN BUG: characterization`.
3. Версии зависимостей не обновлять. Новые зависимости — только devDependencies из утверждённого мной списка.
4. Ключи только в main, webPreferences не ослаблять, секреты не читать/не печатать/не коммитить.
5. Один шаг = один коммит = одна идея. Перемещение файлов (`git mv`) и правка содержимого — разные коммиты.
6. Тесты не менять ради прохождения (кроме изначально ошибочных — отдельный коммит с объяснением).
7. Удаляешь — докажи: проверь строковые IPC-каналы, className из шаблонных строк, пути из helper.m и
   electron-builder, entry points, scripts. Не уверен — в список «нужно подтверждение», не удаляй.
8. Не изобретай проблемы. Проект уже чистый (0 any, 0 циклов, jscpd 0.22%). Архитектурное изменение —
   только если названа конкретная проблема и решение проще текущего. Никаких слоёв «на вырост».
9. Не можешь проверить (GUI, жесты, права, микрофон, вставка в чужие приложения) → пункт в MANUAL_SMOKE.md.
10. Язык: со мной по-русски; код, коммиты, идентификаторы — по-английски.

## Безопасность среды (это моя реальная машина с выданными правами)
- ЗАПРЕЩЕНО запускать реальный helper с командами: move, click, drag, scroll, key, type, paste, copy,
  activate, voice, gesture, request-permissions; скрипт `test:gesture` — не запускать без моего разрешения.
- Разрешено (read-only): `ping`, `permissions`, `front`, `apps`, `cursor`, `focused`; `watch` — коротко, с жёстким
  таймаутом. `probe` — только после чтения его кода в helper.m на побочные эффекты.
- Тесты НЕ трогают реальный electron-store, Keychain/safeStorage, API-ключи, сеть. electron — `vi.mock`,
  fetch — всегда мок, store — in-memory или tmp-cwd в /tmp.
- Запуск GUI — только по задаче и после предупреждения мне: `env -u ELECTRON_RUN_AS_NODE`, флаг `--no-sandbox`.
- npx: всегда `npm_config_cache=/tmp/npm-cache`.
- ЛОВУШКА: `util.ts:~13` и `context/selection.ts:~32` — busy-loop на `Date.now()` (до 450 мс). С fake timers,
  подменяющими Date, он повиснет навсегда. Мокай эти функции через vi.mock или используй
  `vi.useFakeTimers({ toFake: [...] })` без Date. Busy-loop не переписывать (это смена поведения).
