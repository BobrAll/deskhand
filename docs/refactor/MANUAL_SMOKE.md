# MANUAL_SMOKE — что руками проверяет Александр (T34)

Почему этот файл существует: правила 9 из `RULES.md` — всё, что нельзя проверить из Node-тестов
(GUI, права macOS, жесты, микрофон, вставка в чужие приложения, реальный helper), фиксируется здесь
пунктом с ожидаемым результатом. Тесты (`npm test`, 40 файлов / 967 тестов) покрывают решения,
парсеры, протоколы и состояния; здесь — только то, что живёт по ту сторону процесса Electron.

## Как запускать

```bash
cd /Users/bobr/Desktop/smart-cursor
npm run build            # out/ должен собраться без ошибок
env -u ELECTRON_RUN_AS_NODE npx electron . --no-sandbox
```

Приложение tray-only: иконка в строке меню, окна нет. Если это первый запуск на этой машине —
сначала удалить настройки, чтобы увидеть onboarding: `rm -rf ~/Library/Application\ Support/smart-cursor*`
(уносит и ключи из Keychain-обёртки — вводить заново).

Пометки в шагах: **[O]** — onboarding, **[S]** — настройки, **[H]** — хоткей, **[A]** — агент,
**[V]** — голос/жест, **[X]** — то, что раньше ломалось.

## 1. [O] Первый запуск и права

1. Запустить с пустыми настройками (`onboardingCompleted: false`).
   **Ожидание:** открывается окно онбординга, шаг «Разрешения»; в заголовке три шага
   (Разрешения · Ключ API · Готово), активен первый.
2. Дать все три права (Accessibility, Screen Recording, Microphone) в системных диалогах.
   **Ожидание:** галочки `✓` появляются сами в течение ~1.5 с без перезагрузки окна (опрос раз в 1500 мс),
   кнопки запроса у выданных прав исчезают.
3. Нажать «Пропустить» на шаге прав.
   **Ожидание:** сразу открывается шаг «Ключ API», права не запрашиваются. На этом шаге есть «Назад» —
   он возвращает на шаг прав, где выданные права уже отмечены галочками (без повторного запроса).
   Онбординг можно пройти целиком, ничего не выдавая: «Позже» на шаге ключа ведёт на «Готово».
4. Ввести ключ провайдера на шаге «Ключ API», нажать «Проверить» (кнопка неактивна, пока поле пустое).
   **Ожидание:** при живом ключе — зелёный статус, поле очищается; при мусорном — красный текст ошибки,
   ключ не сохраняется; окно не закрывается само, можно ввести другой ключ.
   *Проверено по коду*: `bundle` после сохранения не перезагружается (`onboarding/App.tsx:57-83`), поэтому
   надпись «Ключ для … уже сохранён» в этом же сеансе не появится — она видна только после перезапуска.
   Это косметика, не блокер; если важно — кандидат в BUGS.
5. Нажать «Начать работу».
   **Ожидание:** окно онбординга закрывается, карточка ассистента при этом НЕ открывается — остаётся
   только tray-иконка. При следующем запуске онбординг больше не открывается, а вместо него
   открывается оверлей (ручной запуск).
   *Проверено по коду*: `onboardingCompleted` выставляется в `true` уже на самом первом запуске
   (`index.ts:192`), до того как пользователь что-то нажал — то есть флаг означает «онбординг показан
   один раз», а не «пользователь его прошёл». Практического вреда нет, но название обманчиво.
6. **[X]** Перезапустить приложение после выдачи Accessibility.
   **Ожидание:** права применяются к новому процессу (это требование macOS, оно же написано в подсказке
   на шаге прав). Если вставка/выделение не работают до перезапуска — это ожидаемо, а не баг.

## 2. [H] Хоткей и базовый поток

1. Нажать `Alt+Space` в Finder.
   **Ожидание:** карточка ассистента появляется рядом с курсором, в фокусе поле ввода, курсор в нём.
2. Нажать `Alt+Space` второй раз.
   **Ожидание:** ничего не «дёргается» и не открывается второе окно (карточка уже открыта).
3. Ввести «что на экране?» и нажать Enter.
   **Ожидание:** ответ печатается постепенно (стрим, не одним куском), курсор мыши не перехватывается.
4. Нажать `Esc` во время стрима.
   **Ожидание:** стрим обрывается, карточка закрывается, вставки не происходит.
5. Нажать `Esc` на пустой карточке (без запроса).
   **Ожидание:** карточка закрывается мгновенно, никаких запросов к провайдеру в консоли.
6. **[X]** Сменить хоткей в настройках на занятую комбинацию (например `Cmd+Space`).
   **Ожидание:** под полем появляется «Комбинация занята — оставлена прежняя.», в поле возвращается
   старый аккорд, он по-прежнему работает (регистрация не теряется). Затем задать свободный
   (`Alt+Shift+J`) — новый работает сразу, пункт в tray-меню стал «Открыть ассистента (Alt+Shift+J)».

## 3. [X] Три приложения подряд

Проверить, что контекст собирается не из закешированного окна, а из активного.

1. Safari: открыть статью, выделить абзац, `Alt+Space` → «сократи».
   **Ожидание:** ответ по выделенному тексту; в карточке видно, что контекст — выделение, а не скриншот.
2. Finder: кликнуть по файлу (выделения текста нет), `Alt+Space` → «что это за файл?».
   **Ожидание:** используется скриншот активного окна; ответ про Finder, а не про Safari.
3. Заметки (Notes): поставить курсор в текст без выделения, `Alt+Space` → «продолжи мысль».
   **Ожидание:** контекст — окно Notes; вставка (⌘Enter) идёт в Notes, а не в предыдущее приложение.
4. Открыть 1Password (в списке исключённых), `Alt+Space`.
   **Ожидание:** карточка на экране не остаётся (может мигнуть и закрыться), запрос провайдеру не уходит,
   в консоли — строка `[overlay] active app is on the exclusion list — nothing collected`. Ни выделение,
   ни скриншот не читаются.
   *Проверено по коду*: при исключённом приложении `overlay.ts:574` закрывает окно, поэтому баннер
   «Приложение в исключениях» (`App.tsx:1182`) в этом сценарии не показывается — он виден только если
   приложение стало исключённым уже при открытой карточке.

## 5. [A] Агентный сценарий

1. **[S]** Вкладка «Агент» → тик «Разрешить управлять мышью и клавиатурой»; «Разрешить печатать текст»
   и «Разрешить горячие клавиши» оставить включёнными; «Сколько раз смотреть на экран заново» = 3.
2. В TextEdit: «напиши в поле привет и нажми Enter».
   **Ожидание:** карточка показывает план (`1/3`), подпись текущего шага, затем «Проверяю результат»
   (`agent/index.ts:418`), затем либо вердикт после проверки, либо честное «не подтвердилось» + попытка
   исправления. Раундов не больше 3 («Сколько раз смотреть на экран заново»).
3. Во время выполнения шевельнуть мышью.
   **Ожидание:** прогон прерывается, в карточке — сообщение об остановке, дальнейшие шаги не выполняются.
4. Повторить и нажать `Esc` в момент между шагами.
   **Ожидание:** остановка по Escape, никаких «дописываний» после. Кнопки «Стоп» в карточке нет
   намеренно (окно click-through) — рядом с подписью висит подсказка «Esc — остановить».
5. Выключить «Разрешить печатать текст», повторить п.2.
   **Ожидание:** шаг печати отбраковывается ещё на нормализации плана, остальные выполняются;
   в карточке появляется строка «Пропущено: Печать отключена.» (причина — `plan.ts:105`).
6. Выключить агентный режим целиком, нажать хоткей.
   **Ожидание:** карточка пишет «Агентный режим выключен в настройках.» и не предлагает действие.
7. Отозвать Accessibility в системных настройках и повторить.
   **Ожидание:** карточка пишет «Нужен доступ «Универсальный доступ», иначе macOS не даст нажимать за
   вас.», а не про выключенный режим (проверка порядка — `agent/index.ts:113-138`).

## 6. Вставка ответа

1. В TextEdit: `Alt+Space` → «напиши одну строку» → `⌘Enter`.
   **Ожидание:** ответ вставляется в позицию курсора; буфер обмена восстанавливается (вставить `⌘V`
   в стороннее приложение — там должно быть прежнее содержимое, а не ответ).
2. Скопировать в буфер картинку, повторить вставку.
   **Ожидание:** после вставки в буфере снова картинка (порядок восстановления: png → bookmark → текст).
3. Сфокусировать окно, которое нельзя активировать (например диалог с модальным окном), и нажать
   `⌘Enter`.
   **Ожидание:** fallback с одним из двух текстов (`paste/index.ts:50` или `:76`) —
   «Не удалось вернуться в исходное приложение — ответ скопирован в буфер обмена.» либо
   «Вставка недоступна в этом поле — ответ скопирован в буфер обмена.»; ответ реально лежит в буфере,
   падения и «залипшего» курсора нет.
4. Кнопка «Заменить» при выделенном тексте.
   **Ожидание:** выделение заменяется ответом целиком, хвост не остаётся.

## 7. [V] Push-to-talk

1. Удержать `Alt+Shift+Space`, сказать фразу, отпустить.
   **Ожидание:** пока клавиша удерживается, в карточке идут бары уровня; после отпускания — фаза
   распознавания, затем текст появляется в поле.
2. Коротко тапнуть `Alt+Shift+Space` (< 300 мс).
   **Ожидание:** запись начинается, но на отпускании отменяется (`voice/index.ts:285`, `longEnough()`):
   ничего не транскрибируется и не вставляется, карточка возвращается в обычный вид.
3. Держать дольше `maxDurationMs` (120 с по умолчанию).
   **Ожидание:** запись закрывается сама, транскрипт всё равно приходит, микрофон освобождается.
   *Проверено по коду*: в UI `maxDurationMs` не редактируется (`VoiceTab.tsx:276` только показывает
   «Запись обрывается на N с»), поэтому либо держать две минуты, либо править значение в
   `settings.json` вручную перед запуском.
4. В режиме `command` с включённым «Отправлять сразу, не дожидаясь Enter» сказать фразу.
   **Ожидание:** распознанный текст сразу уходит в ассистент как отправленный запрос (карточка
   начинает отвечать), а не просто ложится в поле.
5. Переключить «Что делать с распознанным» на `dictate`.
   **Ожидание:** карточка не остаётся на экране: распознанный текст вставляется прямо в активное
   приложение, без интерпретации как команды (`voice/index.ts:379-386`).
6. `Esc` во время записи.
   **Ожидание:** запись отменяется, ничего не вставляется, микрофон закрывается (иконка в меню-баре
   macOS гаснет).
7. Отозвать микрофон в системных настройках и нажать push-to-talk.
   **Ожидание:** понятное сообщение про микрофон, без зависания в фазе «запись».

3. Ввести мусорный base URL (`htp://x`).
   **Ожидание:** поле подсвечено, настройки не пишутся на диск (hold), при возврате валидного значения —

4. Изменить `temperature`/`maxTokens` и подождать 450 мс, затем закрыть окно.

5. Нажать «Удалить» рядом с сохранённым ключом.
   **Ожидание:** ключ исчезает из Keychain; в карточке — «Добавьте ключ <провайдер> в настройках, чтобы

6. Вкладка «Приватность»: добавить приложение в исключённые, затем удалить.
   **Ожидание:** список сохраняется между перезапусками; удаление сразу снимает блокировку в оверлее.
7. Вкладка «Поведение»: выключить «Делать скриншот, когда нет выделения».
   **Ожидание:** следующий запрос без выделения не снимает экран (в логах нет захвата), ответ строится
   на одном названии приложения. Чип «Экран» в карточке при этом выключен, но нажимается вручную — и
   тогда кадр снимется для этого запроса. Чипы контекста называются «Текст · N» и «Экран»
   (`App.tsx:1117-1146`) и видны в развёрнутой карточке до первого ответа.
   *Проверено по коду*: предупреждения «Модель не принимает изображения» здесь НЕ будет — оно вешается
   только при `flags.includeScreenshot` (`overlay.ts:263-269`).
8. Вкладка «Поведение»: включить «Скрывать поле ответа при переключении на другое приложение»,
   затем открыть карточку и кликнуть в другое приложение.
   **Ожидание (фактическое, см. BUGS.md R4):** карточка НЕ скроется — тик пишется на диск, но его
   значение не читает ни одно место в `main/`. Если карточка скрылась — значит R4 починили, обнови
   `BUGS.md`.

## 12. hud / pointer / cursor

> **Важно (проверено по коду в T34):** окно `hud` в текущей сборке не показывается никогда —
> `hud.update()` не вызывается ни из одного места (`index.ts:38` создаёт его, `index.ts:239` уничтожает,
> `ipc.ts:108` отдаёт `getState`). Индикатор голоса живёт в самом оверлее: `overlay/App.tsx:938` —
> «бары вместо поля ввода». Поэтому пункт 1 ниже проверяет **отсутствие** чипа, а не его наличие.
> Кандидат в A2 (мёртвый код), поведение не менял.

1. Push-to-talk (§7.1) и посмотреть на экран вокруг курсора.
   **Ожидание:** никакого чипа у курсора НЕ появляется (см. врезку выше); бары уровня видны в карточке,
   на месте поля ввода. Курсор не перехватывается, фокус не крадётся.
2. Агентный прогон (§5.2).
   **Ожидание:** курсор-указатель агента двигается к цели, подпись не «прыгает», после окончания хода
   исчезает; при отмене — исчезает сразу, а не через несколько секунд.
3. Запрос с рисованием (§4.1).
   **Ожидание:** нарисованные фигуры появляются и исчезают по завершении/закрытии карточки; на экране не
   остаётся «залипших» линий после `Esc`.
4. Подвести курсор к нижнему/верхнему/правому краю экрана и повторить п.1.
   **Ожидание:** карточка (она и есть индикатор) остаётся внутри рабочей области — не обрезана краем
   экрана и не уезжает под Dock/меню-бар.

## Что считать провалом

Пункт провален, если поведение расходится с «Ожиданием» **или** в консоли появляется необработанное
исключение / `Uncaught`. Провал не чинить в этой сессии: запись в `BUGS.md` (где, как воспроизвести,
ожидание, что по факту) + строка в `PROGRESS.md`.

Отдельно: пункты, помеченные **[X]**, — это места, где тесты уже нашли или почти нашли расхождение
(R1–R3 в `BUGS.md`). Если они ведут себя «странно, но как описано в BUGS.md» — это ожидаемо.
